요새 포켓몬 카드에 빠졌슨,, 근데 되팔이의 값으로 사고 싶지는 않고 그렇다기에 새벽같이 용산가서 웨이팅 하기에는 난 직장인이다. 그래서 선택한게 편의점에 간혹 들어오는 재고들!!

포켓몬 카드는 편의점에 들어오는 즉시 사라진다. 매장에 가봐야 없고, 전화로 물어보기도 애매하다. 그래서 "우리 동네 편의점에 카드가 들어오는 순간"을 잡아 알림을 주는 감시기를 만들었다.

결론부터 말하면 이마트24와 세븐일레븐 둘 다 로그인 없이 점포별 실시간 재고를 조회할 수 있다. 다만 두 체인 모두 "앱에서만 되는 기능"처럼 보이게 만들어 놓아서, 그 껍데기를 벗기는 데 대부분의 시간을 썼다.

중간에 "세븐일레븐은 앱 전용이라 불가능하다"고 결론 내렸다가 뒤집힌 구간이 있는데, 그게 이 글에서 제일 쓸모 있는 부분이라 그대로 남긴다.

## 배경

편의점 4사(GS25·CU·세븐일레븐·이마트24)는 재고 조회를 전부 모바일 앱 전용으로 안내한다. 웹에서 재고를 보는 공식 경로는 없고, 세븐일레븐은 거기에 로그인 필수 + 챗봇이라는 조건까지 붙어 있다.

하지만 요즘 앱의 상당수는 네이티브 화면이 아니라 웹뷰다. 웹뷰면 그 안에서 도는 건 결국 HTTP 요청이고, 그렇다면 밖에서도 같은 요청을 보낼 수 있다. 이 가정에서 시작했다.

## 1. 이마트24 

검색하다 `everse.emart24.co.kr/stock/goods/search`라는 주소가 잡혔다. 브라우저로 열어보니 로그인 없이 200. 앱 '재고확인' 화면의 웹뷰가 그대로 노출되어 있었다.

페이지 안의 jQuery를 읽으니 엔드포인트가 세 개였다.

| 용도 | 엔드포인트 |
|---|---|
| 주변 점포 | `POST /store/getNearStoreList` (lat, lon, pageCnt, order_by=distance) |
| 상품 검색 | `POST /stock/stock/search` (searchWord, currentPage) |
| 점포별 재고 | `GET /api/stock/v2/stock-search/store` (searchPluCode, bizNoArr) |

### 30분을 날린 함정: charset

상품 검색을 아무리 쳐도 `{"totalCnt":0,"productList":[]}`만 왔다. "포켓몬"도 0건, "우유"도 0건, "바나나"도 0건. 전부 0건이면 보통 차단을 의심하게 된다.

원인은 차단이 아니라 인코딩이었다.

```
Content-Type: application/x-www-form-urlencoded
→ {"totalCnt":0,"productList":[]}

Content-Type: application/x-www-form-urlencoded; charset=UTF-8
→ {"totalCnt":79, ...}
```

`charset`을 명시하지 않으면 서버가 한글 검색어를 ISO-8859-1로 읽는다. 그리고 에러 없이 조용히 0건을 돌려준다. 이게 제일 고약한 종류의 실패다. 4xx가 떴으면 5분 만에 알아챘을 것을, 200 OK에 빈 배열이라 "API가 막혔나" 쪽으로 한참 샜다.

덤으로, Git Bash에서 `curl --data-urlencode "searchWord=우유"`로 넘겨도 똑같이 0건이 온다. `curl.exe`가 Windows 인자를 CP949로 받아서 그걸 URL 인코딩하기 때문이다. 검증 스크립트를 셸이 아니라 파이썬/Bun으로 짜야 하는 이유가 여기 있다.

### 응답 모양이 판정을 단순하게 만들어줬다

점포별 재고 API는 그 상품을 취급하는 점포만 행으로 준다. 수량이 0이어도 행은 있고, 아예 안 파는 점포는 행 자체가 없다.

```json
{"storeGoodsQty": [
  {"BIZNO":"22556","PLU_CD":"8800286279143","BIZQTY":30},
  {"BIZNO":"21746","PLU_CD":"8800286279143","BIZQTY":0}
]}
```

이 성질 덕에 판정이 아주 단순해진다.

- 행 없음 → 이 동네에서 안 파는 상품. 가끔만 확인하면 된다
- 행 있고 수량 0 → 취급하는데 지금 없음 = 재입고 감시 대상
- 0 → N으로 바뀌는 순간이 곧 재입고

요청 1번이 상품 1개 × 전 점포(48곳)를 덮는다. 응답은 50~800ms.

## 2. 세븐일레븐

처음에 잘못된 엔드포인트에 꽂힘. 

- `www.7-eleven.co.kr` / `m.7-eleven.co.kr`을 다 뒤져도 재고 메뉴 자체가 없다
- 공식 안내는 "앱 설치 → 로그인 → 우리동네 상품찾기 → 챗봇"
- `stock.7-eleven.co.kr`이라는 서브도메인이 살아 있긴 했다 (Spring Boot, Imperva WAF 뒤). 그런데 경로를 모르니 404만 반복

그래서 "앱 전용 + 로그인 필수라 웹에서는 불가능, 앱 트래픽을 캡처해야 한다"고 정리했다. 이 결론은 관측된 사실에 근거했지만, 결과적으로 틀렸다. 틀린 이유는 뒤에 나온다.

### mitmproxy로 캡처

PC에 mitmproxy를 띄우고 아이폰을 프록시로 붙였다. 아이폰은 앱이 사용자 설치 CA를 신뢰하기 때문에 탈옥 없이 된다 (안드로이드 7+는 앱이 사용자 인증서를 무시해서 에뮬레이터나 루팅이 필요하다).

```powershell
pip install mitmproxy
mitmdump -s capture.py --listen-port 8081
```

캡처 애드온은 7-eleven 도메인만 필터링하도록 짰다. 그리고 아무것도 안 잡혔다.

여기서 중요한 분기가 있었다. 파일이 비어 있을 때 가능성은 셋이다.

1. 트래픽이 프록시를 안 탔다
2. 탔는데 내 필터가 도메인을 잘못 짚었다
3. 탔는데 인증서 고정(pinning)으로 TLS가 깨졌다

mitmdump 콘솔에는 플로우가 줄줄 흐르고 있었으니 1번과 3번은 탈락. 2번이었다. 그래서 관심 없는 트래픽도 host+path만 따로 기록하도록 애드온을 고쳤다. 본문은 안 남긴다.


다시 캡처하니 이렇게 나왔다.

```
PUT  new.7-elevenapp.co.kr/api/v1/member/sso/appLoginCheck
GET  new.7-elevenapp.co.kr/api/v1/auth/session/is-authenticated
GET  new.7-elevenapp.co.kr/api/v1/product/pages
POST new.7-elevenapp.co.kr/api/v1/stock/search/stores      ← 이것
```

`7-eleven.co.kr`이 아니라 `7-elevenapp.co.kr`이었다. 홈페이지 도메인만 뒤지고 있었으니 영원히 못 찾을 수밖에.  도메인캡쳐해서 하니 잘 되었당. 

그리고 요청 헤더를 보니 `sec-fetch-site: same-origin`에 `referer`가 웹 URL이었다. 네이티브 앱이 아니라 웹뷰라는 뜻이다. 즉 PC에서도 같은 요청을 보낼 수 있다.

실제로 `is-authenticated`를 PC에서 쳐보니 로그인 없이 200이 왔다.

### 두 번째 관문: 좌표가 암호화되어 있다

캡처된 요청 본문은 이랬다.

```json
{
  "searchType": "list",
  "myLat": "RgznMrtVswUI7biFzYzidWsy6RZSxAayb+BbcNpUT2cy...",
  "myLng": "yd8Nc0Y4kor/H8XrrRndDofR+i0iic5z4X6hV5Jab5qa...",
  "order": "stock",
  "smCd": "138027",
  "ignoreRateYn": "Y"
}
```

위경도가 256바이트 base64 — RSA-2048 암호문이다. 좌표를 마음대로 넣을 수 없으면 "우리 동네" 조회가 안 된다.

웹뷰의 Nuxt 번들(`app.js`, 1.2MB)에서 암호화 함수를 찾았다.

```js
function encryptRSA(e) {
  const a = useNuxtApp().$config.public.rsaPublicKey;
  const n = convertDerToPem(a);
  return forge.util.encode64(
    forge.pki.publicKeyFromPem(n)
      .encrypt(e, "RSA-OAEP", { md: sha256, mgf1: { md: sha256 } })
  );
}
```

RSA-OAEP(SHA-256), 공개키는 페이지 런타임 설정에 그대로 박혀 있다. 공개키니까 당연히 공개되어 있는 게 맞고, 그래서 재현도 된다. Bun의 WebCrypto로 열 줄이면 끝난다.

```ts
const key = await crypto.subtle.importKey(
  "spki", der, { name: "RSA-OAEP", hash: "SHA-256" }, false, ["encrypt"]);
const cipher = await crypto.subtle.encrypt(
  { name: "RSA-OAEP" }, key, new TextEncoder().encode(String(lat)));
return btoa(String.fromCharCode(...new Uint8Array(cipher)));
```

이걸로 쏘니 200. 점포별 `realStock`이 그대로 나왔다.

### 번들에 있는데 배포 안 된 경로

번들에는 엔드포인트가 두 벌 있었다.

```js
const L = "/api/v1/open/stock/search";   // open 접두사 = 비로그인용
const i = "/api/v1/stock/search";
```

`open` 쪽이 당연히 정답처럼 보이는데, 실제로 치면 404다. 배포가 안 되어 있다. 정작 도는 건 접두사 없는 쪽이고, 그쪽도 비로그인으로 열린다. 번들 코드를 읽는 건 훌륭한 단서지만 그게 지금 살아 있다는 보장은 아니다.

## 3. 감시기 설계에서 실제로 문제가 됐던 것들

### 판정은 (상품 × 점포) 칸 단위로

알림 단위를 상품으로 잡으면 "어느 점포에 들어왔는지"를 잃는다. 그래서 상태를 `(상품, 점포)` 칸으로 들고 있는다.

- `0 → N` → 재입고 🔔
- 처음 보는 칸에 재고 있음 → "지금 가면 살 수 있음" 🔔
- 이미 있는데 +5 이상 → 재입고 🔔
- 그대로 / 줄어듦 / 계속 0 → 조용

같은 칸은 15분 쿨다운을 둔다. 수량이 0↔N을 깜빡여도 알림이 도배되지 않게.

### 요청 예산은 순번 배분으로

감시 대상이 91종이고 요청 간격이 2초면 한 바퀴에 3분이 걸린다. 노리는 확장팩이 3분에 한 번만 확인되는 건 너무 느리다.

그래서 순번을 세 갈래로 나눴다.

| 갈래 | 비중 | 설명 |
|---|---|---|
| 우선 | 6칸 중 4칸 | 지정한 확장팩. 취급 점포가 없어도 자주 본다 |
| 일반 취급 | 6칸 중 1칸 | 이 동네에서 파는 나머지 |
| 비취급 | 6칸 중 1칸 | 안 파는 상품 |

"취급 점포가 없어도 우선 상품은 계속 본다"가 핵심이다. 신규 취급이 시작되는 순간을 놓치지 않으려면 그렇게 해야 한다. 이 배분 로직은 부수효과 없는 순수 함수로 떼어내서 테스트를 붙였다 — 확률적으로 도는 코드라 눈으로는 검증이 안 된다.

### 검색 인덱스는 재고 DB보다 느리다

가장 실질적인 발견이었다. 신상품 확장팩을 이마트24에서 검색하면 0건이 나온다. 그런데 바코드로 재고 API를 직접 치면 취급 점포가 나온다.

즉 상품 DB에는 이미 들어와 있는데 검색 인덱스가 아직 못 따라온 것이다. 검색 결과만 믿고 감시 대상을 만들면 신상품을, 그것도 제일 중요한 신상품을 통째로 놓친다.

여기에 체인별 상품명 차이까지 겹친다.

```
이마트24   : 포켓몬)포켓몬카드(인페르노X)
세븐일레븐  : 비젼)포켓몬확장팩(인페르노X)
```

검색어 하나로는 양쪽이 다 안 걸린다. 그런데 바코드는 두 체인이 같은 값을 쓴다. 그래서 한쪽 검색에 잡힌 상품의 바코드를 다른 쪽에 물어보는 식으로 목록을 합쳤다.

결과: 이마트24 43종 → 53종, 세븐일레븐 13종 → 38종. 늘어난 10종은 전부 실제 취급 중이면서 검색에는 안 뜨던 것들이었다.

## 4. 폰 알림은 앱을 만들 필요가 없다

감시기는 PC에서 도는데 사람은 밖에 있다. 여기에 앱을 만드는 건 과하다. [ntfy](https://ntfy.sh)면 충분하다.

- 가입 불필요, 토픽 이름만 정하면 끝
- 앱스토어의 `ntfy` 앱에서 그 토픽을 구독
- 서버는 HTTP POST 한 번

```ts
await fetch("https://ntfy.sh", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    topic, title, message,
    priority: 4,          // 잠금화면에서도 소리
    click: mapUrl,        // 누르면 그 점포 지도로
  }),
});
```

두 가지 주의점.

- 한글은 반드시 JSON 본문으로. ntfy의 `Title:` 헤더 방식은 ASCII만 받아서 한글 제목이 깨진다
- 토픽 이름이 곧 비밀번호다. 가입이 없으니 이름을 아는 사람은 누구나 읽고 쓸 수 있다. `pokemon` 같은 짧은 이름은 남의 알림과 섞인다. 랜덤 문자열을 쓸 것

## 삽질 기록

API보다 환경 설정에서 더 많이 막혔다. 다음에 또 할 사람(=미래의 나)을 위해 남긴다.

| 증상                   | 원인                                                                  |
| -------------------- | ------------------------------------------------------------------- |
| 검색이 항상 `totalCnt: 0` | `Content-Type`에 `charset=UTF-8` 누락. 에러 없이 0건                        |
| 셸에서만 한글 검색 실패        | `curl.exe`가 Windows 인자를 CP949로 받음                                   |
| `mitmdump` 명령을 못 찾음  | 관리자 권한 없는 `pip`가 `--user`로 설치. `%APPDATA%\Python\Python3xx\Scripts` |
| 폰이 프록시에 연결 안 됨       | `ipconfig`의 WSL/Hyper-V 가상 어댑터(`172.x`)를 골랐음. Wi-Fi 어댑터 주소여야 함  |
| Safari는 되는데 앱만 실패    | 인증서 설치 후 설정 → 일반 → 정보 → 인증서 신뢰 설정 토글을 안 켬                       |
| 캡처 응답이 전부 깨진 글자      | `flow.response.raw_content`는 gzip 원본. `.content`를 써야 압축이 풀린다        |
| 필터에 아무것도 안 걸림        | 도메인을 잘못 짚음. 모르는 트래픽의 주소만이라도 따로 기록해 두면 이걸 5분에 판별할 수 있다           |

## 결론

1. "앱 전용"은 대체로 "공식 웹 경로가 없다"는 뜻이지 "HTTP가 아니다"라는 뜻이 아니다. 요즘 앱의 그런 화면은 십중팔구 웹뷰다
2. 못 찾았다와 없다는 다르다. 세븐일레븐은 도메인 하나를 잘못 짚어서 "불가능"이라는 결론까지 갔다. 관측 범위를 결론에 명시해야 한다
3. 에러 없이 빈 결과를 주는 API가 제일 위험하다. charset 하나로 30분, 도메인 하나로 그보다 더 썼다
4. 정상 상태가 빈 결과인 도메인에서는 대조군이 필수다. 바나나맛우유가 없었으면 "카드 재고 0"과 "요청이 틀림"을 끝까지 구분 못 했다
5. 검색 API는 그 서비스의 전부가 아니다. 재고 DB가 검색 인덱스보다 빨랐고, 그 차이가 정확히 제일 중요한 신상품이었다

## 부록: 예의 있게 긁기

남의 서버를 두드리는 일이니 선은 지키는 게 좋다.

- 조회만 한다. 장바구니·주문·선점 같은 쓰기 동작은 붙이지 않았다. 알림을 받으면 사람이 직접 간다
- 폴링 간격은 넉넉히. 상품당 2초, 요청 1건이 전 점포를 덮으니 실제 부하는 사람이 앱을 쓰는 수준과 비슷하다
- 예산을 배분한다. 안 파는 상품은 6번에 1번만, 노리는 상품에 순번을 몰아준다. 전수 조사를 매번 돌리지 않는다
- 실패하면 물러난다. 조회 실패 시 간격을 2배씩 늘려 최대 10분까지 backoff
- 캡처 파일에는 로그인 토큰이 그대로 들어간다. `.gitignore`에 넣고, 커밋 전에 반드시 확인할 것
