## 배경

Claude Code를 하루 종일 붙여 쓰기 시작하면 토큰이 어디로 새는지 감이 잡힌다. 크게 세 군데다.

1. 비싼 모델이 기계적인 일까지 한다. typecheck 돌리고 "통과" 한 줄 보고하는 일에 최상위 모델을 쓸 이유가 없다.
2. 허락 프롬프트 왕복. 도구 한 번 쓸 때마다 "실행할까요?" → "응" 이 오가면, 그 턴마다 컨텍스트 전체가 다시 올라간다.
3. 읽지 않아도 되는 걸 읽는다. 파일을 통째로 읽고, 로그를 통째로 붙이고, 이미 아는 걸 다시 설명한다.

그래서 설정을 이 세 갈래로 손봤다. 특별한 도구를 쓴 게 아니라 Claude Code가 이미 제공하는 것들(서브에이전트 모델 지정, 권한 설정, 훅, 메모리)을 조합한 것이다. 이 글은 그 조합을 한 번에 정리한 것.

---

## 결과 먼저 보기

| 갈래 | 수단 | 효과 |
|---|---|---|
| 모델 분리 | 서브에이전트마다 `model:` 명시 (sonnet / haiku) | 구현·검증 토큰이 메인 모델 단가에서 빠져나감 |
| 왕복 제거 | `defaultMode: bypassPermissions` + allow/deny + 차단 훅 | 도구 호출마다 생기던 확인 턴 소멸 |
| 읽기 좁히기 | 에이전트 정의에 "토큰 효율" 섹션 고정 | 파일 통째 읽기·로그 통째 인용 금지 |
| 컨텍스트 다이어트 | 메모리는 인덱스 한 줄만 로드, 규칙 파일은 짧게 | 세션 시작 시 올라가는 고정 비용 최소화 |
| 모델 우회 | 반복 사무는 훅(스크립트)이 처리 | 모델이 페이지 읽고 쓰는 토큰 자체가 없음 |

## 1. 서브에이전트 모델 다운시프트 — 가장 효과가 크다

메인 세션은 PM만 한다. 실제 구현·리뷰·검증은 서브에이전트가 하고, 각 에이전트 정의 파일 프론트매터에 모델을 명시한다.

```markdown
---
name: app-task
description: 일감을 받아 조사 → 수정 → typecheck까지 수행. 커밋·푸시는 하지 않는다.
model: sonnet
---
```

| 역할 | 모델 | 이유 |
|---|---|---|
| 구현(app-task) | sonnet | 코드 수정은 중간 등급으로 충분 |
| 리뷰(app-review) | sonnet | 변경분만 보는 리뷰는 범위가 작다 |
| QA(app-qa) | haiku | typecheck·lint·E2E는 "돌리고 결과 요약"이 전부 |
| PM(메인 세션) | 최상위 | 판단·취합·사용자 소통만 |

핵심은 `inherit`를 쓰지 않는 것이다. 모델을 비워두면 메인 세션 모델을 상속받아 서브에이전트까지 전부 비싼 단가로 돈다. "까다로운 건은 그때만 올린다"는 원칙으로, 호출할 때 "이건 opus로"라고 한 줄 붙이면 된다.

비유하면 팀장이 직접 테스트 서버 로그를 읽고 있는 상황을 없애는 것이다. 팀장은 결과 보고만 받으면 된다.

---

## 2. 에이전트 정의에 "토큰 효율" 섹션을 박아둔다

모델을 나눠도, 에이전트가 파일을 통째로 읽고 로그를 통째로 옮기면 그만큼 새 나간다. 그래서 세 에이전트 파일 모두에 같은 이름의 섹션을 고정했다.

```markdown
## 토큰 효율 (반드시 지킬 것)

- 목표에 필요한 파일·라인만 읽는다. 대용량 파일은 grep으로 위치를 먼저 좁힌 뒤
  해당 구간만 읽는다. 파일을 통째로 읽지 않는다.
- 로그·코드를 통째로 붙여넣지 않는다. 핵심 몇 줄만 `파일:라인`으로 발췌한다.
- 명령 출력은 통과면 "통과" 한 줄, 실패면 핵심 에러 줄만.
- 결과는 정해진 형식으로 간결하게. 사고 과정·시도 나열·중복 설명 금지.
- (리뷰) 변경분과 무관한 파일 정독 금지. 순수 포맷 churn은 건너뛴다.
- (QA) 이미 떠 있는 dev 서버가 있으면 새로 띄우지 않는다.
```

특히 "결과 형식을 정해두는 것"이 효과가 좋았다. 형식이 없으면 에이전트가 친절하게 과정을 다 서술하는데, 그건 메인 세션 컨텍스트로 그대로 흘러들어온다. 메인이 받는 건 결론·diff·제안 커밋 메시지 정도로 제한했다.

## 3. 허락 왕복 제거 — 대신 안전은 deny와 훅으로

권한 모드를 `bypassPermissions`로 두면 도구 호출마다 뜨는 확인이 사라진다. 이게 토큰과 무슨 상관인가 싶지만, 확인 한 번이 곧 모델 턴 한 번이다. 하루에 수백 번이면 무시할 수 없다.

```json
{
  "permissions": {
    "defaultMode": "bypassPermissions",
    "allow": [
      "Read", "Grep", "Glob", "Edit",
      "Bash(git status)", "Bash(git diff *)", "Bash(git log *)",
      "Bash(bun run *)", "Bash(bunx prettier *)", "Bash(bunx playwright *)"
    ],
    "deny": [
      "Read(**/.env*)", "Read(**/*.pem)", "Read(**/secrets/**)",
      "Write(**/.env*)", "Write(.github/workflows/*)",
      "Bash(rm -rf *)", "Bash(sudo *)", "Bash(git push *)",
      "Bash(curl * | sh)", "Bash(chmod *)"
    ]
  }
}
```

풀어주는 대신 못 하게 할 것을 deny에 명확히 적는다. 시크릿 읽기, 강제 삭제, sudo, push, 원격 스크립트 실행은 어떤 상황에도 안 된다.

deny 패턴으로 부족한 건 훅으로 막는다. `rm`은 `rm -rf`만 막으면 `rm 파일`이 통과하니, PreToolUse 훅으로 삭제 명령 전체를 차단하고 "사용자 승인이 필요하다"는 메시지를 돌려주게 했다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/block-rm.sh\"" }]
      }
    ]
  }
}
```

```bash
#!/usr/bin/env bash
# block-rm.sh — rm/rmdir/unlink가 들어간 Bash 호출을 차단한다
cmd=$(jq -r '.tool_input.command // empty')
if echo "$cmd" | grep -Eq '(^|[;&|[:space:]])(rm|rmdir|unlink)(:space:|$)'; then
  echo "🚫 파일 삭제 명령은 차단되어 있습니다. 사용자에게 명시적으로 허락을 받으세요." >&2
  exit 2
fi
```

정리하면 "자율성은 최대로, 비가역 작업만 못 하게"다. 확인 턴을 없애면서도 미추적 파일을 임의로 지우는 사고는 구조적으로 막힌다.

재미있는 부작용 하나. 이 글을 저장하려고 쉘 heredoc으로 파일을 쓰다가 훅에 막혔다. 본문에 `rm -rf` 예시 문자열이 있었기 때문이다. 훅은 명령의 의도를 모르고 문자열만 본다는 걸 기억해 두면, 이런 경우엔 쉘 대신 파일 쓰기 도구를 쓰면 된다.

## 4. 세션 시작 고정 비용 — 메모리와 규칙 파일 다이어트

세션이 열릴 때마다 올라가는 것들이 있다. 전역 규칙 파일, 프로젝트 규칙 파일, 메모리 인덱스. 이건 매 턴 컨텍스트에 실리는 고정 비용이라 짧을수록 좋다.

- 메모리는 인덱스 한 줄만. 메모리 하나가 파일 하나이고, 인덱스 파일에는 `- [제목](파일) — 한 줄 훅`만 적는다. 본문은 필요할 때 그 파일만 읽는다. 70개가 넘는 메모리가 있어도 세션 시작 비용은 70줄이다.
- 전역 규칙 파일은 100줄 안쪽. 커밋 이모지 규칙, 승인 절차처럼 모든 프로젝트에 필요한 것만 남기고, 프로젝트별 규칙은 프로젝트 파일로 내렸다.
- 레포가 이미 기록하는 건 메모리에 넣지 않는다. 코드 구조, 지난 수정, git 이력은 메모리로 다시 적을 이유가 없다.

## 5. 모델 우회 — 반복 사무는 훅 스크립트가 한다

일감을 완료로 넘길 때마다 주간 업무일지 페이지에 링크를 추가해야 했다. 처음엔 모델이 페이지 HTML을 읽고 → 셀을 찾고 → 링크를 넣고 → 다시 써 올렸다. 매번 페이지 통째 두 번이다.

이걸 PostToolUse 훅으로 옮겼다. 이슈 상태 전환 도구가 성공하면 스크립트가 알아서 업무일지를 갱신한다. 모델은 페이지를 보지도 않는다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "mcp__<이슈트래커>__transitionIssue",
        "hooks": [{ "type": "command", "command": "node ~/.claude/scripts/update-worklog.mjs" }]
      }
    ]
  }
}
```

원칙은 단순하다. 입력과 출력이 매번 같은 모양인 작업은 모델 일이 아니다. 스크립트로 빼면 토큰이 0이 되고, 실수도 없어진다.

## 하지 않은 것, 주의할 것

- thinking 토큰 상한, 컨텍스트 자동 압축 관련 환경변수는 건드리지 않았다. 최적화보다 결과 품질이 먼저다. 위 다섯 갈래만으로 체감이 충분했다.
- allow 목록은 주기적으로 청소해야 한다. 세션에서 한 번 허락한 일회성 명령(특정 파일에 대한 sed, 특정 URL curl)이 allow에 그대로 쌓인다. 토큰에는 영향이 없지만 설정 파일이 지저분해진다. 붙박이 패턴(`Bash(bun run *)`)으로 일반화하고 나머지는 지운다.
- bypass 모드는 deny·훅과 반드시 짝이다. deny 없이 bypass만 켜는 건 절약이 아니라 사고 예약이다.
- 모델을 내렸는데 결과가 흔들리면 그 건만 올린다. 전체 기본값을 다시 올리지 않는다.

## 배운 점

- 토큰은 "모델 단가 × 턴 수 × 컨텍스트 크기"다. 세 항 중 하나만 줄이면 한계가 있고, 셋을 동시에 건드려야 체감이 온다. 모델 분리(단가), 권한 왕복 제거(턴 수), 읽기 제한·메모리 다이어트(컨텍스트)가 각각 한 항씩 맡는다.
- 가장 큰 절약은 "모델이 안 하게 만드는 것"이었다. 훅으로 빠진 작업은 토큰이 줄어든 게 아니라 사라졌다.
- 자율성을 올릴수록 안전장치는 코드로 내려야 한다. 확인 프롬프트를 없애는 대신 deny 패턴과 차단 훅이 그 자리를 맡았고, 그래서 안심하고 풀 수 있었다.

---

## 한 줄 요약

비싼 모델은 판단만, 기계적인 일은 싼 모델이나 스크립트로, 확인 왕복은 deny·훅으로 대체해서 없애고, 컨텍스트에 올라가는 건 인덱스 한 줄로 줄인다.
