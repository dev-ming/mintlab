글쓰기 화면 위에 전체 화면으로 뜨는 "투표 만들기" 레이어를 만들었다. 데스크톱에서는 잘 돌아갔는데, 폰에서 테스트하던 동료가 한마디 했다. "뒤로가기 누르면 글이 다 날아가는데요?"

맞다. 레이어는 별도 페이지가 아니라서 URL이 그대로고, 안드로이드 뒤로가기 버튼을 누르면 브라우저는 "이 페이지에서 나가라"로 받아들인다. 레이어만 닫히는 게 아니라 글쓰기 화면 전체가 이탈되고, 쓰던 본문까지 사라진다. 모바일 사용자는 "뒤로가기 = 지금 뜬 거 닫기"를 기대하니 정확히 그 반대로 동작한 셈이다.

이 글은 그걸 고치면서 정리한 내용이다. 결론은 History API로 가짜 칸을 하나 쌓고, popstate에서 레이어만 닫는다인데, 곁가지로 밟은 함정 세 개가 더 쓸모 있을 것 같아 같이 적는다.

---

## 브라우저 히스토리는 스택이다

브라우저 탭은 방문 기록을 스택으로 들고 있다. 페이지를 이동하면 한 칸 쌓이고, 뒤로가기는 맨 위 한 칸을 뺀다. 여기까지는 다 아는 얘기.

덜 알려진 건 두 가지다.

1. URL을 바꾸지 않고도 칸을 쌓을 수 있다. `history.pushState()`.
2. 뒤로가기로 칸이 빠질 때 페이지 이동 없이 이벤트만 받을 수 있다. `popstate`.

이 둘을 합치면 "URL은 그대로인데 뒤로가기 한 번을 가로채는" 구조가 된다. 모달, 바텀시트, 전체 화면 레이어에 뒤로가기를 붙일 때 쓰는 표준 패턴이다.

---

## 기본 구조

레이어를 여는 순간 칸을 하나 쌓는다.

```ts
// 레이어가 마운트될 때
window.history.pushState({ ...window.history.state, overlay: true }, '');
```

스택은 이렇게 된다.

```
[목록] → [글쓰기] → [글쓰기 + 레이어]   ← 지금 여기
```

세 번째 칸은 URL이 두 번째와 같다. 브라우저 입장에서는 "같은 주소에 한 번 더 왔다"고 기억할 뿐이다. `state`에 `overlay: true` 같은 표식을 넣어두면 나중에 "이 칸은 내가 만든 것"인지 구분할 수 있다.

사용자가 뒤로가기를 누르면 브라우저가 맨 위 칸을 빼고 `popstate`를 쏜다. URL은 안 바뀌므로 페이지는 그대로고, 우리 코드가 받아서 레이어를 닫는다.

```ts
useEffect(() => {
  const onPop = () => {
    onClose(); // 레이어만 닫는다. 글쓰기 화면은 그대로.
  };
  window.addEventListener('popstate', onPop);
  return () => window.removeEventListener('popstate', onPop);
}, [onClose]);
```

여기까지가 뼈대다. 그런데 이대로 두면 바로 두 가지가 어긋난다.

---

## 함정 1 — 버튼으로 닫으면 칸이 남는다

레이어에는 보통 X나 Done 버튼이 있다. 버튼으로 닫으면 쌓아둔 칸이 그대로 남아서, 그다음 뒤로가기가 한 번 헛돈다(URL이 같은 칸으로 이동하므로 화면 변화 없음). 사용자는 "뒤로가기가 안 먹네?" 하고 한 번 더 누르게 된다.

그래서 버튼으로 닫을 때는 직접 `history.back()`을 호출해 칸을 걷어낸다.

```ts
const closeByButton = () => {
  pushed.current = false;
  skipNextPop.current = true; // 아래 popstate는 우리가 만든 것
  window.history.back();
  onClose();
};
```

`history.back()`도 `popstate`를 발생시키므로, 핸들러가 "사용자 뒤로가기"로 오해해서 `onClose`를 두 번 부르지 않게 플래그로 한 번 무시한다. 실제로는 `back()` 직후 컴포넌트가 언마운트되어 리스너가 먼저 사라지는 경우가 많아 플래그가 안 쓰일 때도 있지만, 타이밍에 기대지 않는 편이 안전하다.

---

## 함정 2 — "정말 닫을까요?" 모달 뜬 상태에서 또 뒤로가기

편집 중에 뒤로가기를 누르면 바로 닫지 않고 확인 모달을 띄워야 한다. 첫 구현은 이랬다.

```
popstate → 편집 중이면 모달만 띄움 (칸은 이미 빠진 상태)
  Keep editing → 칸을 다시 pushState
  Discard     → 닫기
```

리뷰에서 바로 걸렸다. 모달이 떠 있는 동안은 칸이 없는 상태다. 그때 뒤로가기를 한 번 더 누르면 글쓰기 화면 자체를 빠져나간다. 안드로이드에서 뒤로가기를 연타하는 사용자는 흔하다.

고치는 방법은 단순하다. 모달을 띄우는 순간 칸을 즉시 다시 쌓는다.

```ts
const onPop = () => {
  if (skipNextPop.current) { skipNextPop.current = false; return; }
  if (!isDirty()) { onClose(); return; }
  window.history.pushState({ ...window.history.state, overlay: true }, ''); // 바로 복구
  setShowDiscard(true);
};
```

이러면 Keep editing은 모달만 닫으면 되고, Discard만 `closeByButton`처럼 칸을 소비하면 된다. 모달 상태에서 뒤로가기를 또 눌러도 다시 `popstate` → 모달 유지로 끝난다.

## 함정 3 — 프레임워크 라우터와 공용 스크롤 로직이 popstate를 듣고 있다

이게 제일 음험했다.

### 라우터가 state를 검사한다

일부 SPA 라우터는 `history.state`에 자기 표식을 심어두고, `popstate`가 왔을 때 그 표식이 없으면 "외부에서 건드린 히스토리"로 보고 페이지를 새로고침한다. 우리가 `pushState({ overlay: true })`처럼 state를 통째로 갈아끼우면 표식이 사라져 뒤로가기 한 번에 전체 리로드가 날 수 있다.

그래서 기존 state를 반드시 펼쳐서 보존한다.

```ts
window.history.pushState({ ...window.history.state, overlay: true }, '');
```

쓰는 라우터가 `pushState`를 패치해서 알아서 표식을 복사해 주는 경우도 있지만, 그 내부 동작에 기대기보다 명시적으로 보존하는 게 낫다.

### "뒤로가기면 스크롤을 복원한다" 로직이 오염된다

앱에 보통 이런 공용 컴포넌트가 있다. "라우트가 바뀌면 맨 위로 스크롤, 단 뒤로가기로 온 거면 브라우저 복원에 맡긴다." 구현은 대개 `popstate`에서 플래그를 세우고, 다음 경로 변경 effect에서 플래그를 보고 리셋한다.

문제는 우리 레이어가 만드는 `popstate`는 경로가 바뀌지 않는다는 점이다. 플래그만 세워지고 리셋되지 않은 채 남는다. 그 뒤 사용자가 글을 올려 목록으로 이동하면, 공용 컴포넌트는 "뒤로가기로 온 거구나" 하고 스크롤을 맨 위로 올리지 않는다. 증상이 레이어와 한참 떨어진 화면에서 나와서 원인 찾기가 어렵다.

해결은 공용 컴포넌트 쪽에서 경로가 실제로 바뀐 popstate만 인정하는 것이다.

```ts
const lastPath = useRef(window.location.pathname);
const onPop = () => {
  if (window.location.pathname === lastPath.current) return; // 같은 경로 = 오버레이용
  isPop.current = true;
};
```

같은 경로의 `popstate`는 다른 오버레이가 생겨도 안전하게 무시된다.

## 남는 것 하나 — 레이어가 열린 채 다른 곳으로 이동하면

레이어가 열려 있는 동안 알림 딥링크나 세션 만료 리다이렉트로 라우트가 바뀌면, 쌓아둔 칸이 하나 남는다. 언마운트 시점에 `history.back()`을 부르면 라우트 이동과 겹쳐 더 위험해서 일부러 안 걷어낸다. 결과는 "그 뒤 뒤로가기 한 번이 헛도는" 정도라 허용했다. 레이어가 열린 동안 아래 화면을 `inert`로 막아 두면 이 경로 자체가 거의 생기지 않는다.

---

## 정리

| 상황 | 해야 할 일 |
| --- | --- |
| 레이어 열림 | `pushState({ ...history.state, overlay: true }, '')` — 기존 state 보존 |
| 뒤로가기(popstate) | 편집 중 아니면 닫기. 편집 중이면 칸을 즉시 다시 쌓고 확인 모달 |
| 버튼으로 닫기 | `history.back()`으로 칸 소비, 그로 인한 popstate는 1회 무시 |
| 공용 스크롤 복원 로직 | 경로가 바뀐 popstate만 인정 |
| 열린 채 라우트 이동 | 칸 하나 잔류 허용, 아래 화면 `inert`로 발생 자체를 줄임 |

테스트는 Playwright의 `page.goBack()`으로 충분히 잡힌다. "레이어 열고 goBack → 레이어만 닫히고 URL 동일", "입력 후 goBack → 모달, 또 goBack → 모달 유지", "Keep editing → 유지, Discard → 닫힘" 세 가지면 위 함정이 전부 커버된다.
