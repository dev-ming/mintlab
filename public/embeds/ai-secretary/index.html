01 · 기존 방식

매일 아침 탭 4개를 열어서 확인했습니다

도구하던 일문제분/일
Jira내 일감, 릴리즈 버전별 남은 일 확인필터를 매번 다시 걸어서 봄. 마감 가까운 건 가끔 놓침__
Sentry밤새 생긴 운영 오류 확인Jira에 이미 있는지 하나씩 찾아봄. 중복 티켓 만든 적 있음__
Calendar회의, 보고 일정 확인개발할 수 있는 시간은 머릿속으로 계산__
Slack멘션, DM, 스레드 확인답해야 하는 것과 참고용이 섞여서 빠뜨림__
퇴근 기록Jira 댓글, 업무일지하루 끝나고 기억나는 대로 작성__

다 따로 보다 보니 뭐부터 할지 정하는 데만 매일 시간이 꽤 들었습니다.

원칙 02 · 구체적으로 지시

/morning 지시문은 이렇게 나눠서 썼습니다

PRODUCT
뭘 만들지
  • 한 화면짜리 브리핑
  • 오늘 꼭 할 일은 3개까지
  • 일정, 시간표 제안, Slack 정리
  • 항목마다 출처 링크 달기
PROCESS
어떤 순서로
  • Jira → Sentry → 캘린더 → Slack 순서로 읽기
  • Sentry 오류는 기존 티켓과 겹치는지 먼저 확인
  • 빈 시간 계산해서 일감 배치
  • 릴리즈 마감과 우선순위로 정렬
BEHAVIOR · 멈출 지점
어떻게 행동할지
  • 읽기는 마음대로 해도 됨
  • 티켓 생성, 일정 등록, 메시지 발송 전에는 멈추고 물어보기
  • 확실하지 않으면 "추정"이라고 쓰기
  • 도구 하나가 안 되면 추측으로 채우지 말고 비워두고 알려주기

원칙 03
결과 의심하기
AI 결과를 의심해보고 실제로 잡아낸 것들
정책 수치화면에 나가는 유예 기간이 7일로 돼 있었는데, BE 상수와 맞춰보니 10일이 맞았음
원인 확정운영 DOM 오류 원인이 브라우저 번역기인 걸 확인하고 일감 4개로 나눔
교차 검증구현 에이전트 결과를 리뷰·QA 에이전트가 따로 검증. 리뷰·QA는 수정 권한 없음
원칙 04
책임은 사람이
결과 책임은 제가 지는 구조
확인 후 실행쓰기 작업은 전부 제가 확인. 푸시와 완료 처리는 제가 직접
규칙 누적사고가 한 번 나면 규칙으로 저장해서 다음부터 자동 적용. 메모리 파일 106개

데이터연동 범위는 내 멘션, DM, 내 캘린더까지만. 사내 정책도 확인
